# GPCN™ Provider

The GPCN™ (Global Private Cloud Network™) provider lets you manage your GPCN™ infrastructure with Terraform. You'll describe VPCs, subnets, security groups, elastic IPs, L2 segments, VPN gateways and VPN connections, virtual machines (VMs), GPU instances, volumes, SSH keys and resource groups in configuration, and Terraform builds and changes them for you.

This page walks you through installing the provider and giving it an API key. By the end you'll have a configuration that Terraform can plan.

New to GPCN™ with Terraform? Start with the [Getting started](guides/getting-started) guide.

## Prerequisites

- Terraform 1.5 or later
- A GPCN™ account
- An [API key](https://hub.gpcn.com/docs/identity-and-access/credentials/api-keys) whose role covers the resources you'll manage

## Example Usage

```terraform
terraform {
  required_providers {
    gpcn = {
      source  = "Global-Private-Cloud-Network/gpcn"
      version = "~>1.6.0"
    }
  }
}

# The provider reads GPCN_HOST and GPCN_API_KEY from the environment,
# so the block can stay empty.
provider "gpcn" {}

# Look up a data center to build in
data "gpcn_datacenters" "chicago" {
  name        = "Chicago 1"
  vpc_capable = true
}

resource "gpcn_vpc" "main" {
  name          = "main"
  datacenter_id = data.gpcn_datacenters.chicago.datacenters[0].id
  cidr          = "10.10.0.0/16"
}
```

Run `terraform init` to install the provider, then `terraform plan` to see what it will build.

## Authentication

The provider signs in with an API key. Set the key and the API address as environment variables, and you can leave the `provider` block empty:

```shell
export GPCN_HOST="https://api.gpcn.com"
export GPCN_API_KEY="<your API key>"
```

You can also set `host` and `api_key` in the `provider` block. Keep the key out of any file you commit to version control.

The provider checks the key when it starts. If the key is revoked or expired, the plan stops with a clear message. If it expires within seven days, you'll see a warning.

## Permissions and resource groups

Every VM, GPU instance, volume, VPC and L2 segment belongs to one [resource group](https://hub.gpcn.com/docs/identity-and-access/people/resource-groups). If you don't set `resource_group_id`, the resource joins your organization's Default group.

What a key can do comes from its role. An organization-wide role acts on resources in the Default group. To create or change resources in any other group, the key needs a role scoped to that group. [Roles and permissions](https://hub.gpcn.com/docs/identity-and-access/roles-and-permissions) lists what each role allows.

## Timeouts and retries

Creating a VM or a VPC is an asynchronous job, and the provider waits for it to finish. Three optional settings control that wait:

- `polling_timeout` is how long the provider waits for a job, in seconds. The default is 600 (10 minutes).
- `request_timeout` is how long a single request to the API can take, in seconds. The default is 60.
- `max_retries` is how many times a request that fails for a temporary reason is tried again. The default is 3.
